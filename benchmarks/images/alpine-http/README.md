# Alpine HTTP benchmark VM

This builds an x86_64 Alpine 3.20.10 system disk with OpenRC, the `linux-virt`
kernel, OpenSSH, and BusyBox HTTP on port 8080. `GET /health` returns HTTP 200
and the two bytes `ok`. There is no GUI, cloud-init, guest agent, or application
framework. The initial resource target is 256 MiB RAM, one vCPU, and a 2 GiB
virtual disk. All packages needed at runtime are installed during the build.

## Build

Use an x86_64 Linux host with root access, mount namespaces, loop devices and
partition scanning. On Debian/Ubuntu install:

```sh
sudo apt-get install bash curl ca-certificates coreutils util-linux e2fsprogs qemu-utils qemu-system-x86 openssh-client python3
```

From the repository root:

```sh
ssh-keygen -t ed25519 -f "$HOME/.ssh/niep-bench"  # choose your own passphrase
sudo benchmarks/images/alpine-http/build.sh \
  --authorized-keys "$HOME/.ssh/niep-bench.pub" \
  --network-map benchmarks/images/alpine-http/example/network-map \
  --output "$PWD/benchmarks/images/alpine-http/output"
```

Use an existing public key or an authorized_keys file if preferred. Private keys
are never copied into the guest. The root account accepts public keys by default;
password authentication is disabled. The output directory must not already
contain `alpine-http-base.qcow2`; rebuilding never overwrites an existing image.
`--cache DIR` changes the input cache directory (default: `cache` beside the
script). `--network-map FILE` is optional; omit it for a generic base.

The build downloads the official minirootfs at a fixed URL and verifies its
committed SHA-256. `packages.sha256` locks the complete APK dependency closure,
including the kernel and BusyBox. APK signatures and SHA-256 are checked; there
is no floating package resolution. A populated cache permits an offline rebuild.
Retain that cache with experiment artifacts: Alpine mirrors may eventually remove
old APK versions. A missing pinned package fails the build rather than upgrading
silently. To deliberately refresh packages, resolve the closure of `alpine-base
linux-virt syslinux openssh busybox-extras` against Alpine v3.20/main in an Alpine
3.20 chroot (`apk fetch --recursive`), regenerate the SHA-256 file, review it, and
revalidate. The runtime package list and final disk checksum accompany the output.

Reproducibility means fixed source/package inputs and configuration, not identical
QCOW2 bytes: filesystem identifiers, timestamps, and bootloader metadata vary.
Caller-provided public keys, optional password hash, and network map are additional
inputs and should be recorded with an experiment. SSH host keys are absent from
the base and generated by Alpine's sshd service on each instance's first boot.
Machine IDs, DHCP leases, and random seeds are not carried into clones.

The builder installs Syslinux BIOS boot code into a temporary disk file, using a
private mount namespace. It never partitions a host disk. It detaches loop devices
and removes temporary files on success/failure; an unmount failure preserves the
workspace and reports the device for manual recovery. Do not run concurrent builds
against the same output/cache directories. Generated disks and caches are ignored
by Git. No TinyCore disk or template is modified.

## Register with NIEP

The topology and VM validators now accept `alpine-http` alongside the existing
TinyCore and Click disks. NIEP's `VMImageStore` discovers `VEM/IMAGES/<DISK>.qcow2` and the matching
`<DISK>.xml`; there is no registry command. The matching template
`VEM/IMAGES/alpine-http.xml` is included in the repository. Install the built disk
from the repository root before defining the topology:

```sh
sudo install -m 0444 benchmarks/images/alpine-http/output/alpine-http-base.qcow2 VEM/IMAGES/alpine-http.qcow2
```

Do not replace a registered base while instances are running. Ensure the libvirt
QEMU account can traverse the repository's parent directories and read its images,
and that the host's libvirt `default` network is active (`virsh -c qemu:///system
net-info default`). See the existing `make vm-libvirt-perms` convention for the
Vagrant environment. SELinux/AppArmor rules may also need to allow this image path.

NIEP's additional `vnNIEP` network uses the dedicated `virbrNIEP` bridge. This
avoids collisions with Vagrant networks that may reserve `virbr1` even while
inactive.

NIEP already makes a separate full disk copy under `VEM/IMAGES/<VM-ID>/` during
`createVM`, then rewrites the template's name, UUID, memory, vCPUs, management MAC,
and disk path. This implementation preserves that mechanism: independent writable
copies avoid backing-chain lifetime issues and need no runtime changes. The base
is installed read-only. Disk copying belongs to topology preparation; record it
separately from boot-to-health time. Temporary validation VMs use QCOW2 overlays.
NIEP instances retain their private disk/SSH keys across stop/start; destroy and
recreate the instance for a fresh-clone trial.

Start the normal NIEP daemon as described in the project README, then:

```sh
.venv/bin/niepctl define benchmarks/images/alpine-http/example/topology.json
.venv/bin/niepctl topoup
.venv/bin/niepctl vm management bench-vm01
.venv/bin/niepctl mininet cmd h1 curl --noproxy 10.20.0.2 --fail http://10.20.0.2:8080/health
.venv/bin/niepctl topodestroy
```

The example uses the MAC mapping supplied in the build command. Each additional
VM needs a unique ID, management MAC, data MAC, bridge ID, and IP address. Multiple
MAC mappings can live in one reusable base; only mappings for NICs actually present
are applied. Do not clone topology MAC/IP values into simultaneous instances.

## Management, data networking, and SSH

The template places the management virtio NIC at PCI `0000:00:03.0` on the BIOS
`pc` machine. NIEP connects it to libvirt's `default` NAT network, which supplies
DHCP. The `niep-network` OpenRC oneshot discovers NICs through sysfs before
`networking`; it identifies management by PCI location, not Linux interface name.
Other NICs are brought up without an IP by default. An optional
`/etc/niep-network.conf` maps MAC addresses to IPv4 CIDR values or `dhcp`. It is
regenerated into `/etc/network/interfaces` on every boot, so there is no persistent
interface-name/MAC binding from the build host.

NIEP attaches Mininet NICs as virtio devices at slots starting at `0x0a`. It creates
host bridges and links but does not assign guest IP addresses or provide DHCP on
every data link. The example mapping gives its data NIC `10.20.0.2/24`, paired with
Mininet host `h1` at `10.20.0.1/24`. Static data addressing avoids waiting for a
nonexistent DHCP server. Use `dhcp` only on links with a DHCP server. The HTTP
server binds all guest addresses after networking starts, so it works over either
management or Mininet. No extra runtime network daemon is added.

For a generic base, configure a data address over management SSH after boot:

```sh
ssh -i "$HOME/.ssh/niep-bench" root@MANAGEMENT_IP
# Inside the guest, locate the device by its topology MAC, then configure it:
for dev in /sys/class/net/*; do
  if [ "$(cat "$dev/address")" = 52:54:02:20:10:01 ]; then
    iface=${dev##*/}
    ip addr replace 10.20.0.2/24 dev "$iface"
    ip link set "$iface" up
  fi
done
```

For startup measurements use the preinstalled mapping instead, so SSH configuration
is not part of the measured interval. NIEP supplies the interfaces before boot. If
manually hotplugging NICs later, update the map and restart `niep-network` followed
by `networking`; HTTP already listens on all addresses.

NIEP's `vm management` uses the host ARP table, not libvirt DHCP lease discovery.
If it has no entry yet, find the address with `virsh -c qemu:///system net-dhcp-leases
default`, then ping that address from the host before retrying `vm management`.
Native `ssh -i KEY root@IP` works without changing NIEP. The legacy
`niepctl vm ssh ID USER PASSWORD` runs `sshpass` and requires a password argument.
To use password authentication, supply a caller-generated SHA-512 crypt hash file
at build time with `--password-hash FILE` (e.g. generate interactively using
`openssl passwd -6`, store with mode 0600). This enables root password login in
that build. There is no built-in password. Prefer key authentication; the legacy
CLI passes its password in process arguments. Benchmarks should use the same
credential policy for every instance.

See [VALIDATION.md](VALIDATION.md) for executed commands, actual results, and host
limitations.

## Validation and troubleshooting

With the daemon running and no topology defined, run three fresh startup cycles:

```sh
.venv/bin/python benchmarks/images/alpine-http/smoke-test.py
.venv/bin/python benchmarks/images/alpine-http/verify-cleanup.py
```

The smoke test polls HTTP through `h1` for up to 30 seconds and checks status
200 and the exact body `ok`. It reads the command output from the CLI's JSON
response. Each cycle stops and destroys its topology. Reported elapsed time
includes `topoup`, CLI calls, and polling; it is a functional check rather than
an isolated guest boot measurement. Set `NIEP_SOCKET` for a custom daemon socket.

After building, run on the Linux host as a user with access to `/dev/kvm`:

```sh
benchmarks/images/alpine-http/validate.sh \
  benchmarks/images/alpine-http/output/alpine-http-base.qcow2 \
  "$HOME/.ssh/niep-bench"
```

The private key must match a built-in public key and support noninteractive SSH
(use an agent for a passphrase-protected key). Validation creates a disposable
overlay and QEMU VM with 256 MiB/one vCPU, waits for HTTP 200 plus body `ok`,
authenticates SSH, checks HTTP on a second NIC, requests guest `poweroff`, waits
for QEMU to exit, and removes temporary resources. The second NIC uses the example
MAC/address; validation reports whether it was configured at boot, and configures
it via SSH if necessary to support a generic base. Use the NIEP topology check
above to verify the actual Mininet path. KVM is preferred; TCG is the fallback. Failure retains serial/QEMU logs and
removes the overlay. Host ports are ephemeral and bound only to loopback.
An additional check exercises NIEP's actual VM adapters and system libvirt without
Mininet. Run from the repository root in an environment with NIEP and Python libvirt
installed, and permission to manage system libvirt:

```sh
.venv/bin/python benchmarks/images/alpine-http/validate-niep.py \
  benchmarks/images/alpine-http/output/alpine-http-base.qcow2 \
  "$HOME/.ssh/niep-bench"
```

It uses `VMImageStore` and `VM.createVM/applyVM/upVM`, verifies management DHCP,
HTTP and SSH, powers off, and removes its temporary domain/disks. It uses a private
image store under `/var/tmp`; it does not register images or modify the running
NIEP daemon's topology. Full Mininet validation uses the topology commands above.

Run validation twice to check fresh instantiation; neither run modifies the base.

For NIEP boots, `virsh -c qemu:///system console bench-vm01` displays the serial
console (exit with Ctrl+]). Key-only images expose boot messages but require SSH
for login; with a supplied password the root console permits login too. Useful
guest checks are `rc-status`, `rc-service niep-httpd status`, `ip addr`,
`cat /etc/network/interfaces`, `dmesg`, and `busybox-extras httpd --help`.
SSH host keys and first-boot key generation are intentional VM startup costs.

Download/build/register before timing. Measure readiness through the Mininet data
link, not just process creation or management SSH. Match container tests to Alpine
3.20, BusyBox HTTP, the same body/port, and comparable network addressing. This
image tooling does not implement the benchmark harness.
